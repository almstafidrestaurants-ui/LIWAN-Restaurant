# LIWAN ADMIN — تحديث صور وأسماء الأصناف من الهاتف

## ما الجديد؟
- من لوحة **أسعار المنتجات** اضغط **تعديل الاسم والصورة** بجانب أي صنف **قديم أو جديد**.
- اختر الصورة مباشرة من **معرض الصور على الهاتف** (زر اختيار ملف)، ثم غيّر اسم الصنف واضغط **حفظ الاسم والصورة والسعر**.
- لإضافة صنف جديد، انتقل إلى **إضافة صنف**، اختر القسم والاسم والسعر، واختر الصورة من الهاتف.
- تُضغط الصورة تلقائيًا إلى JPEG صغير وتُخزّن في **Cloud Firestore**، وبالتالي لا حاجة لرفع الصورة إلى GitHub ولا لشراء Blaze.
- تُزامن الأسماء والصور والأسعار مباشرة في منيو الزبائن عبر مستمعي Firestore.
- تصميم المنيو ودخول المالك بكلمة مرور فقط بقيَا كما هما.

## مهم جدًا قبل التجربة
1. ادخل إلى Firebase Console > Firestore > Rules واستبدل القواعد بالقواعد الجديدة الموجودة في `firestore.rules` ثم اضغط **Publish**.
2. فك ضغط ملف `LIWAN_GALLERY_GITHUB_UPDATE.zip` وارفع **الملفات الموجودة داخله** إلى جذر المستودع GitHub، وليس ZIP ذاته.
3. لا تحذف مجلد `images/` أو الصور الموجودة.
4. بعد نجاح GitHub Pages افتح owner.html وسجّل الدخول بكلمة المرور الحالية.
5. اختبر تغيير الاسم والصورة لصنف، وافتح المنيو على هاتف آخر أو نافذة خاصة للتحقق.

## تنبيهات وحدود
- لا تستخدم Firebase Storage ضمن Spark؛ هذا الإصدار يحفظ **صورًا مضغوطة** في Firestore وليس ملف الصورة الأصلي.
- ستكون الصور العامة مرئية لزبائن المنيو، وحجم الصورة المحدد نحو 85 كيلوبايت أو أقل لتقليل التحميل.
- طريقة الصور هذه مناسبة لمطعم صغير وعدد محدود من صور التعديل. عند استخدام صور كثيرة أو حركة زيارات مرتفعة، ستزيد أحجام التنزيل واستهلاك حصص Firestore، وقد نحتاج تخزين صور مخصصًا لاحقًا.
- لا تُنشر كلمة المرور في ملف GitHub، وقواعد Firestore لا تسمح بالتعديل إلا لـ UID المالك.
- ليس لدينا اتصال مباشر بحساب Firebase، ولذلك **القواعد والملفات لم تُنشر تلقائيًا**. يجب نشرها في حسابك.

## تطبيق LIWAN ADMIN على Android
إذا فتحت صفحة الإدارة من تطبيق Android القديم ولم يظهر معرض الصور عند لمس زر اختيار الملف،
استخدم مشروع Android Studio المعدل `LIWAN_ADMIN_ANDROID_GALLERY_SOURCE.zip` لبناء نسخة APK جديدة.
هذا ليس ملف APK جاهزًا؛ لم يتم بناء التطبيق أو اختباره على الهاتف.

## ملاحظة عن ملفات GitHub
فقط ارفع ملفات ZIP المخصص لـ GitHub، ولا ترفع `firestore.rules` إلى GitHub باعتبار ذلك نشرًا لقواعد Firebase؛
القواعد تُنشر بشكل مستقل من Firestore > Rules > Publish.
